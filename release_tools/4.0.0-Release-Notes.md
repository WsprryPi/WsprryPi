## Direct GPIO transmission on Raspberry Pi 5 and CM5

**Use a Raspberry Pi 5 or Compute Module 5 as a GPIO transmitter.**
WsprryPi 4.0 supports RF output from the Pi's RP1 hardware through
**RP1-GPIO-CLK-DKMS**, the dedicated clock-output driver developed for this
capability.

Choose **GPIO4 or GPIO20** in Setup, with route status and recovery controls.
Run the Pi's own transmission schedule or use it as a remote GPIO transmitter
in Fleet. The installer supplies the driver, matching kernel headers, and
build tools on supported Pi 5-family systems. Installation and pin selection
leave transmission disabled; enabling transmission is a separate action.

## One station, a fleet of transmitters

**Control a mixed fleet of Pis and WsprryPicos while continuing the controller's own local transmissions.** Manage up to **32 remote outputs**, each with its own mode, frequency, message, and schedule, from **Setup → Fleet**.
The WsprryPi Transmitter Protocol, **WTP/1**, delivers each complete job in
advance so the transmitter handles its own timing.

### Control transmitters and schedules

- **Find and name devices.** Discover USB Picos and nearby network devices,
  or add a network address manually. Save devices for later use.
- **Schedule each output.** Run WSPR, QRSS, FSKCW, DFCW, or timed test tones
  where supported. Fleet WSPR schedules send one frame at a time.
- **Manage outputs independently.** Pause, stop, or edit one output without
  replacing other schedules. Failed or uncertain work pauses the affected
  assignment. Reconcile its state before resuming; missed slots are not replayed.
- **Take local control at a remote Pi.** End remote work immediately or let the
  current transmission finish. Local takeover cancels that output's remote
  schedule and returns control to its operator.

### Configure and maintain Picos

- **Set station and network details.** Edit callsign, locator, reported power,
  device name, and Wi-Fi. Supported firmware provides compound callsigns and
  extended locators through WSPR Type 2 and Type 3 messages.
- **Save setup in stages.** Save valid fields while completing the rest later.
  Applying saved station progress is a separate action. Invalid entries and
  unconfirmed changes remain available for correction and review.
- **Configure RF hardware.** Select supported direct GPIO or Si5351 settings,
  GPIO drive strength, amplifier-enable pin and polarity, amplifier lead and
  tail timing, and filter selectors. Hardware changes use the indicated
  apply/restart workflow. GPIO drive and reported WSPR power are separate.
- **Use GPS/PPS and time controls.** Configure supported GPS inputs and inspect
  time, location, and oscillator-calibration information. Direct GPIO and
  Si5351 have independent corrections and manual residual trim. Set device
  time from the browser and configure access policies where supported.
- **Manage standalone operation.** Edit a Pico's own schedules and settings
  from the Pi, with explicit save actions for each task.
- **Maintain firmware over USB.** Check an image, install firmware, and resume
  or recover interrupted updates. Full flash erase is a separate action that
  removes firmware and saved data without creating a backup. Firmware
  maintenance blocks conflicting changes; installation and erase require USB.

Picos connect over USB or a supported network connection. Remote Pis use GPIO
or a Si5351. Controls depend on the selected device's capabilities. Adding a
device or saving settings does not start transmission. Remote operation
requires the documented experimental setting.

**Plain LAN connections are unencrypted.** Use them on a network whose users
you trust to control the transmitters. Losing contact does not confirm that
a transmitter has stopped.

## Precompiled executables

Install a compiled executable for Raspberry Pi OS Bookworm or Trixie on
supported 32-bit and 64-bit systems, including Pi 1 and Pi Zero. Automatic
selection matches the OS release and userspace architecture, avoiding
application compilation, build dependencies, and temporary build swap.
Pi 5 driver preparation has separate build requirements.

For Pico firmware maintenance, the installer retains a compatible picotool or
downloads a verified, USB-capable prebuilt package. Picotool is never compiled
on the Pi. Source installations check available memory and disk-backed swap
and manage temporary build swap under the documented installer policy.

## Logs from your station and Picos

- **Read Pico logs over dedicated USB.** Select attached Pico log sources,
  control collection, and distinguish their records from local Pi messages.
- **Forward and collect UDP logs.** Enable optional forwarding and explicit-peer
  collection, with source and relay information visible in Logs. Imported
  records are not forwarded again. UDP logging is disabled by default, and
  delivery can lose packets.

## Other station capabilities

- **Regional and custom WSPR frequencies.** Choose Default, Preset, or Custom
  dial frequencies by band, including legacy and WRC-15 choices for 60 m.
  Previews show the resulting RF frequency and preserve custom values.
- **Frequency calibration.** Combine a system-clock estimate with measured
  residual correction for GPIO output. Optional Pi 5/RP1 direct PPS calibration
  measures its separate RF clock against a qualified PPS input. Pi 1–4 use
  OS/Chrony host-clock estimation. Si5351 has separate PPM, reference-clock,
  and crystal-load settings. UTC synchronization alone does not calibrate RF.
- **Test Tone controls.** Choose a band or enter an exact RF frequency. The
  operating mode is restored when the tone ends.
- **Filter switching.** Bands can share a selector pin when their polarity
  agrees. GPIO26/27 are available; GPIO4/20 choices account for the RF output.
- **Si5351 through a USB I2C adapter.** Select a stable MCP2221A adapter identity
  on Linux, or use the native macOS Si5351 source build. Select the exact
  adapter and address; a missing device does not select another automatically.
  macOS is a source-build option without signed or notarized binary packages.
- **Support bundles from the browser.** Collect, review, and download
  diagnostics, including process and resource snapshots. Sending an encrypted
  copy for private support requires separate consent; creation does not upload it.
- **Local-network operation without Internet.** Use the web interface on an
  isolated physical LAN. Downloads and online support need Internet access;
  scheduled transmissions need a suitable clock.
- **WSPR and QRSS Spots.** Choose either service from the Spots menu.
- **Web interface upgrades.** Installation checks interface files for local
  changes and provides options for handling customizations.

## Fixed since 3.2.1

Corrections to behavior shipped in 3.2.1:

- Setup reports **Saved** only when the acknowledgement matches the latest
  edits. ([#343](https://github.com/WsprryPi/WsprryPi/issues/343))
- Startup disables the selected transmitter's outputs and blocks transmission
  if that operation fails. ([#347](https://github.com/WsprryPi/WsprryPi/issues/347))
- Disconnected WebSocket handlers release their thread resources, and leaving
  Logs cleans up its owned `journalctl` process.
  ([#349](https://github.com/WsprryPi/WsprryPi/issues/349),
  [#355](https://github.com/WsprryPi/WsprryPi/issues/355))
- Update checks require an eligible release or verified newer branch history
  before offering an upgrade. ([#364](https://github.com/WsprryPi/WsprryPi/issues/364))
- WSPR frequency and offset controls reflow without overlap on narrow screens. ([#367](https://github.com/WsprryPi/WsprryPi/issues/367))
- Invalid or unavailable Si5351 plans return a controlled error.
  ([#368](https://github.com/WsprryPi/WsprryPi/issues/368))
- GPIO PPM correction applies the intended correction direction. Review
  measured correction values when upgrading.
  ([#388](https://github.com/WsprryPi/WsprryPi/issues/388))
- Hardware detection rejects missing or malformed Raspberry Pi revision data.
  ([#430](https://github.com/WsprryPi/WsprryPi/issues/430))
- Install/reinstall safely repairs persistent and runtime service masks before
  replacing the unit, avoiding writes through a mask into `/dev/null`.
  ([#434](https://github.com/WsprryPi/WsprryPi/issues/434))
- GPIO Test Tone targets the requested nominal RF frequency. Clock calibration
  remains separate.
  ([#446](https://github.com/WsprryPi/WsprryPi/issues/446))
- Informational CLI commands complete logger shutdown without hanging.

## Before upgrading

1. **Back up your station.** Keep configuration, executable, local web changes,
   and Pico recovery files. Stop scheduled transmissions and finish interrupted
   firmware work. Restoring an executable alone does not restore settings,
   drivers, or firmware.
2. **Select a matched installation.** Follow the
   [installation guide](https://wsprry-pi.readthedocs.io/en/devel/Install/index.html)
   for OS, architecture, supporting files, and binary selection. An explicit
   binary tag selects the executable only. Verify manually selected downloads
   against their published checksums; architecture and version checks are
   separate from integrity verification.
3. **Review frequencies and calibration.** Standalone WSPR uses USB dial
   frequencies; Fleet WSPR uses an absolute RF center. Check GPIO correction
   values and separate Si5351 settings. For CLI host-clock estimation, use
   `--use-system-clock-frequency-estimate`. Direct PPS requires the documented
   reference, input, and clock-health conditions.
4. **Review network control.** Inbound Pi Plain LAN control is enabled by
   default. Turn off **WTP Server** if remote control is unwanted. Privileged
   browser controls require directly connected network admission; proxies need
   deliberate configuration.
5. **Check Pi and Pico compatibility.** Use compatible application and firmware
   versions, review saved settings, and complete indicated hardware restarts
   before enabling schedules. Existing saved selections are preserved.

Available bands and modes depend on hardware and mode-specific qualification.
A listed band is not universal transmitter support or operating permission.
Investigate Si5351 startup-readiness errors before operation. A faulted or
disconnected adapter cannot confirm that a separately powered clock has stopped.
