# Wsprry Pi v3.2.1 — PHP2Shell Audit and Build Fix

Wsprry Pi 3.2.1 is a maintenance release of the stable `main` branch. It adds a standalone PHP2Shell audit and optional partial mitigations, and fixes incremental build dependency tracking.

See the [operator documentation](https://wsprry-pi.readthedocs.io/en/stable/) for installation and operation. To install or upgrade:

```bash
curl -fsSL installwspr.aa0nt.net | sudo bash
```

## PHP2Shell audit and optional mitigations

The new `scripts/php2shell-mitigate.py` helper checks Debian/Raspberry Pi OS PHP packages and web configuration, reports Apache/PHP-FPM service state, and provides upgrade and restart guidance. It requires Python 3.8 or later and runs separately from the installer.

From a checkout of this release, run a read-only audit:

```bash
python3 scripts/php2shell-mitigate.py
```

Add `--verbose` for the full findings. The report distinguishes installed PHP patch status from optional configuration mitigations and other configuration notes. An older upstream version with a distribution backport requires vendor verification rather than an automatic vulnerable or fixed verdict. A supported system without distribution PHP packages or web configuration is reported explicitly.

**Install your distribution's PHP security updates. Upgrading WsprryPi or changing INI settings alone does not fix PHP2Shell.** See the [PHP security announcement](https://www.php.net/archive/2026.php#2026-10-21-1). After package or configuration changes, fully restart the serving PHP workers and verify the actual web SAPI and effective settings; package metadata alone cannot establish runtime protection.

Operators who need the optional partial mitigations can explicitly apply the managed configuration snippet:

```bash
sudo python3 scripts/php2shell-mitigate.py --apply
```

The helper preserves existing configuration files, backs up an owned snippet before replacing it, and refuses unsafe write paths. Removing PHP's memory limit requires a separate opt-in and is unnecessary for patched PHP; review its memory-exhaustion implications before using it. The helper never installs packages, restarts services, runs PHP requests, or operates transmitter hardware.

Read the [complete audit instructions](https://github.com/WsprryPi/WsprryPi/blob/v3.2.1/scripts/README.md#php2shell-configuration-audit-and-partial-mitigations) for supported configurations, limitations, exit statuses, backups, and rollback. PHP2Shell tracking: [issue #456](https://github.com/WsprryPi/WsprryPi/issues/456).

## Build dependency fix

Generated dependency files are now included from both the top level and the next directory level. Header edits covered by those files correctly trigger recompilation instead of leaving stale objects in an incremental build. A dedicated `build-dependency-regression-test` target checks that the transmitter controller's generated header dependency is loaded.

## Compatibility and validation

- Existing application settings, transmission modes, and scheduling behavior are unchanged from 3.2.0.
- The UI submodule reference advances to its merge commit, whose files are identical to the UI shipped in 3.2.0.
- The installer remains on `main`, with its fallback version updated to 3.2.1.
- This release follows the stable 3.2 series; fleet/Pico/WTP and other 4.0 Beta features are outside its scope.
- Automated validation covers offline PHP fixtures and hardware-free build/runtime regressions. It does not qualify installation, serving PHP workers, service lifecycle, GPIO, timing, or RF output on a live station.
