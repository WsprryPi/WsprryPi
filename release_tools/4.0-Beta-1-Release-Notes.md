# Wsprry Pi 4.0 Beta 1

**Draft — not yet published.** Changes since
[v3.2.0](https://github.com/WsprryPi/WsprryPi/releases/tag/v3.2.0).

## One station, a fleet of transmitters

**Wsprry Pi 4.0 lets one Raspberry Pi control a mixed fleet of other Pis and
WsprryPicos while continuing its own local transmissions.** Manage up to
**eight remote outputs**, each with its own mode, frequency, message and
schedule, from **Setup → Fleet**.

This is made possible by the new **WsprryPi Transmitter Protocol, WTP/1**.
It gives Pis and Picos a common way to receive and run transmissions. Each
transmitter receives the complete transmission in advance and handles its
own timing; individual symbols do not depend on USB or network traffic.

Keep WSPR running on the controller, schedule another band on a second Pi,
and send QRSS from a Pico—all from the same web interface.

## Fleet control

- **Find and name your transmitters.** Discover USB Picos and nearby network
  devices, or add a network address manually. Save devices for later use.
- **Give each output its own schedule.** Run WSPR, QRSS, FSKCW, DFCW or timed
  test tones where the selected transmitter supports them. Fleet WSPR schedules
  send one frame at a time.
- **Manage outputs independently.** Pause, stop or edit one output without
  replacing the other schedules. A failed connection pauses the affected
  schedule; check its status before resuming. Missed transmissions are not
  automatically replayed.
- **Take control at the remote Pi.** Its operator can end remote work immediately
  or let the current transmission finish before returning to local operation.
  Taking local control cancels that output's future remote schedule.

Picos connect over USB or a supported network connection. Remote Pis can use
their GPIO output or a Si5351. Adding a device or saving settings does not
start transmission. Remote operation currently requires an explicit
experimental setting; the setup guide explains how to enable it.

**Plain LAN** connections to Pis or Picos are unencrypted. Use them only on
a network whose users you trust to control the transmitters. Losing a
connection does not confirm that a transmitter has stopped.

## Set up and maintain Picos from the Pi

- **Manage station and device settings.** Edit callsign, locator, reported power,
  Wi-Fi, device name and supported hardware settings from Fleet. Compatible
  firmware supports compound callsigns and extended locators through WSPR
  Type 2 and Type 3 messages.
- **Save setup progress.** Save valid station fields while finishing the rest
  later. Invalid entries stay visible for correction. Applying saved station
  settings is a separate action from saving them or enabling transmission.
- **Set GPIO drive strength.** Choose from the Pico's supported drive settings
  and restart it explicitly to apply a change. Drive strength and reported WSPR
  power are separate settings.
- **Update firmware over USB.** Check an image before installing it, follow the
  on-screen instructions for older firmware, and resume or recover an
  interrupted update. Firmware maintenance blocks conflicting changes.

Full flash erase is a separate action that removes firmware and saved data,
creates no new backup, and leaves the Pico ready for firmware installation.
Pico features depend on the installed firmware; older versions may offer fewer
controls. Firmware installation and erase require USB.

## Other improvements for your station

- **Pi 5-family GPIO transmission.** Support includes Pi 5/CM5 GPIO output using
  the separate RP1 driver, with GPIO4/GPIO20 selection and recovery controls.
  Installing the driver or choosing an output pin does not start transmission.
- **Regional and custom WSPR frequencies.** Choose Default, Preset or Custom
  dial frequencies by band, including the legacy and WRC-15 choices for 60 m.
  The settings show the resulting transmit frequency and preserve custom values.
- **Better frequency calibration.** GPIO correction can combine the system-clock
  estimate with a measured radio-frequency correction. Si5351 has its own PPM,
  reference-clock and crystal-load settings. Clock synchronization alone does
  not calibrate the transmitted frequency.
- **More useful Test Tone controls.** Choose a band or enter an exact RF
  frequency. The previous operating mode is restored afterward, and the old
  GPIO tone-frequency offset is corrected. For remote transmitters, use Fleet's
  timed tones.
- **More flexible filter switching.** Bands can share a selector pin when their
  switching polarity agrees. GPIO26/27 are available, and GPIO4/20 choices
  account for the selected RF output.
- **Clearer feedback and steadier browser use.** Pending edits are no longer
  reported as saved, frequency controls work better on small screens, and
  browser and log-viewer cleanup reduces resource buildup during repeated
  visits. Spots offers both WSPR and QRSS.
- **Support bundles from the browser.** Collect, review and download diagnostics
  without using a shell. Sending an encrypted copy for private support requires
  separate consent; creating a bundle does not upload it.
- **Local-network operation without Internet.** Use the web interface on an
  isolated physical LAN. Downloads and online support still need Internet
  access, and scheduled transmissions still need a suitable clock.

## Before upgrading

1. **Back up your station.** Keep your configuration, executable, local web
   customizations and Pico recovery files. Stop scheduled transmissions and
   finish any interrupted Pico firmware work first.
2. **Choose the right installation.** Precompiled builds cover Bookworm and
   Trixie on supported 32-bit and 64-bit Pis, including Pi 1 and Pi Zero.
   They avoid compiling the application on the Pi. Source installation includes
   better checks and temporary swap support for low-memory systems. Beta
   downloads are not published yet; the default installer follows the stable
   release.
3. **Check calibration after migration.** Review the migration guidance before
   reusing previously measured GPIO correction values. Scripts using the old
   `--use-ntp` option must use `--use-system-clock-frequency-estimate` instead.
4. **Review network control.** The Pi's inbound Plain LAN transmitter control
   is enabled by default. Turn off **WTP Server** if you do not want remote
   control. Browser controls are restricted to directly connected networks;
   remote access through a proxy may need review.
5. **Keep your supporting tools current.** Pico USB firmware maintenance needs
   Python and picotool; Pi installation does not supply picotool. Pi 5 GPIO
   operation also needs the RP1 driver and matching kernel support. Check the
   installation guide for versions and setup.

Available bands and modes depend on the selected hardware. A listed band is
not a promise that every transmitter supports it, and local operating rules
still apply. Reverting to an older executable alone does not restore older
settings, drivers or Pico firmware; keep a complete recovery set.

See the [operator manual](https://wsprry-pi.readthedocs.io/en/devel/) for setup
and use. Engineering details, compatibility limits and release-verification
records are kept in the
[evidence ledger](https://github.com/WsprryPi/WsprryPi/blob/devel/release_tools/4.0-Beta-1-Release-Evidence.md).
