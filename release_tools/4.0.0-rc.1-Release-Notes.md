## Install or update

Run this command on the Raspberry Pi through SSH or a local console to install this release candidate:

```bash
curl -fsSL https://raw.githubusercontent.com/WsprryPi/WsprryPi/refs/heads/devel/scripts/install.sh | sudo env REPO_BRANCH=devel bash -s -- --binary-source release --release-tag v4.0.0-rc.1
```

Rerunning the command reinstalls the same executable version. The installer and supporting files follow `devel`. Follow the installer prompts and reboot if requested.

This is a prerelease. The latest stable release remains `v3.2.1`.

## Fleet controls on Operations

On the Operations page, select “This Pi” or an assigned remote output to inspect status, schedule, pending work, and historical reports. Pause, resume, reconcile, or edit the selected output without replacing other schedules. The controller supports up to 32 independent remote outputs alongside its own local output.

Status freshness, current ownership, and uncertain actions are shown separately. Unconfirmed work retains its recovery state across navigation and controller restarts. Resuming schedules future eligible slots; it does not replay missed transmissions. Losing contact does not confirm that a transmitter has stopped.

## WsprryPico RC.3 support

Use WsprryPico `1.0.0-rc.3` with this release. In Fleet firmware maintenance, choose “Specific version” and enter `1.0.0-rc.3`. Choose “Download and check image” to verify the public image, its provenance, and its settings compatibility before installation is offered. RC.3 remains a prerelease; “Stable release” does not select it.

From the Pi, manage the Pico's standalone morning and evening gray-line windows and optional frequency overrides. Saved-locator day and night schedules can operate without GPS when usable UTC is available. Missing required time or location holds new occurrences. These controls do not change Pi-owned Fleet recurrence or enable the Pico's main schedule merely by saving settings.

## Driver and maintenance updates

Pi 5-family GPIO installations select the published RP1-GPIO-CLK-DKMS `v1.0.0` provider. Driver installation, route selection, and enabling transmission remain separate actions.

Pico configuration handling preserves omitted settings and checks the complete resulting configuration against advertised limits. Firmware selection is explicit, and the image check refuses incompatible images without substituting another version or source. Interrupted updates retain their recovery workflow and verified installer.

## Before upgrading

Back up station settings and recovery files. Disable transmission, finish or reconcile owned jobs, and update the Pi and Pico as a compatible pair. After upgrading, review saved and active hardware settings, complete any required restart, and confirm the intended device, frequency, filter, and load before enabling output.

Use the [versioned RC.1 operator manual](https://wsprry-pi.readthedocs.io/v4.0.0-rc.1/Install/rc1.html) for installation, Fleet operation, firmware maintenance, and recovery.

## Validation and limits

The [release manifest](https://github.com/WsprryPi/WsprryPi/releases/download/v4.0.0-rc.1/publication-manifest.json) identifies the exact application, companion, and documentation sources, along with checksums for all four executables. Software checks cover production network and USB interoperability, configuration handling, and browser workflows.

These checks do not establish physical USB, target installation, service behavior, timing, frequency accuracy, spectral performance, calibrated power, or RF qualification. The 32-output limit is software capacity, not a qualified physical fleet. Automatic Si5351 correction remains experimental. I²C LPF output control is not included in this release.
