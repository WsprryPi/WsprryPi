# SQLite storage and process contract

## Implementation status

This document records the ownership contract and implementation boundary for the [implementation prompt](sqlite-web-service-implementation-prompt.md). The POSIX SQLite store, closed configuration codec, shared catalog, native transaction adapter, complete role-aware source capture, recoverable migration, explicit fresh initialization, and actual executable state entry points are implemented. Hardware-free actual-main checks cover controller and native migration, custom advanced/startup values, simulated native restart, and refusal of missing established state. Production startup rejects active INI input. Authenticated local advanced-settings IPC and a separate browser-service process are implemented. The bounded encrypted archive codec, actual-owner backup capture, independent maintenance broker, authenticated browser download, and nonmutating restore preview are implemented. Confirmed generation replacement, local CLI and Maintenance workflows, worker packaging, persistent destination-review holds, and administrator diagnostic export are implemented. Software fixtures exercise these paths; installed services, target performance, and physical operation remain unqualified.

The inspected baseline is `e4f8c2f364638a57acbc8cb1e7994ffd40269b5a`. The feature branch is `codex/sqlite-web-service`. No device operation or installed-state migration is part of local software validation.

Storage, startup, installer, route maintenance, and the advanced-settings command have focused local software coverage. Fleet assignments/contexts, bounded per-target management journals, and USB/UDP policy are captured through their actual owners and copied in chunks with source-change fencing. The installer selects `/var/lib/wsprrypi/application-state`, a private child of the existing application data root, and never merges or regenerates an active INI. A secret-free listener descriptor carries admitted custom ports to Apache. The independent logging worker receives only a validated policy export outside the private state tree. Fixed stopped-backend route maintenance commits through the native owner; its running-backend read path uses the authenticated local control interface. Storage checks alone do not qualify the integrated service or recovery lifecycle.

## SQLite primitive contract

Use a fixed `state.sqlite3` inside an owner-only selected state directory. Opening established state never creates it. Fresh creation is an explicit operation, refuses existing files, and binds storage format 1 to the selected role and 32-character device/controller identity. No browser input selects a directory or database filename. A process-exclusive directory lock rejects a second normal writer. File, sidecar, mode, ownership, hard-link and symlink checks protect the private namespace; platform adapters must preserve the same intent.

The closed record kinds are full configuration, managed settings, operations, catalog, recurrence authority, recurrence initialization, native local recurrence recovery, and immutable initialization provenance. Each payload remains bounded to the current private-record 1 MiB maximum. Controller storage refuses native recurrence kinds. A transaction changes a bounded subset of these records and an unsigned decimal storage revision together. Each changed record also has a transactional unsigned revision so unrelated catalog changes do not invalidate a local configuration read, while equal-value rewrites still revoke stale observations. Initialization provenance can only be written with the first database decision. Expected-revision comparison is inside the write transaction. A stale compare is a refusal without mutation. The primitive grants no protocol, output, pairing or settings authority and does not interpret a payload as a command.

Schema/role/identity mismatch, malformed or noncanonical revision, unknown records, corrupt database, or observation of another connection's committed changes holds the live owner rather than adopting external edits. Validate production payload shape through the existing typed owners when adapters are connected. Readback does not initialize, repair, migrate, checkpoint or grant authority. Configure WAL/FULL, 4 KiB pages, approximately 1 MiB cache, 1,000-page autocheckpoint and 500 ms busy timeout explicitly; verify their effective values.

Full configuration uses the supported typed persistent whitelist, not public JSON and not raw INI as a new ongoing storage format. Preserve the ten advanced values identified in the implementation prompt and private network policy. Import original source only during admitted migration; completed initialization metadata fences later INI reimport and missing-database fallback. Separate bootstrap provenance from the control contract and from runtime counters. Existing opaque revisions/digests require explicit owner adaptation and current consumer coverage before switching production storage.

The implemented `local-settings/1` codec combines current closed configuration fields with a separate closed private-policy object. It projects validated internal input through the authoritative current field definitions, excludes transient observations, rejects duplicate JSON keys and unsupported formats, preserves canonical Si5351 output/fade values, and needs no station fields in controller mode. Native startup loop/iteration policy is captured from saved source and stored separately from live counters; ordinary saves retain the saved policy. Structural storage validation does not replace the owning runtime's complete semantic/admission checks. The private SQLite snapshot uses the backup API, finishes a destination checkpoint, and never exposes a raw database as an operator download; companion-owner capture and encrypted archives are implemented through the [recovery engine](../../src/application_recovery/README.md).

The POSIX initialization root holds its own owner-only admission lock and `authority.json`; the selected initial database lives in `generation-1`. Native-core migration validates a stable source capture, preserves private `source-*` records, commits the candidate and immutable provenance, validates the actual native owner, and retires the exact original INI to its `.sqlite-migrated` backup before publishing readiness. Interrupted source retirement resumes from the admitted database and backup records without requiring an active INI. Normal open never initializes or resumes migration. The explicit fresh path publishes deterministic role-specific defaults and bootstrap provenance, then retains the existing first-use/setup policy. Fault fixtures terminate actual processes at publication boundaries; they cover source changes, missing established databases, identity/role mismatches, and source retirement with native execution progress. Actual source migration now covers independent companions and early executable dispatch. Installer fixtures cover state admission, listener discovery, and retaining a SQLite-capable candidate after a late transition failure. Actual installation and service qualification remain outstanding.

Controller retirement authority retains its original namespace identity when assignment storage moves. The immutable database initialization record seals that original namespace; the retirement owner accepts its trusted digest separately from the new live assignment path. It does not reopen the retired source path, rewrite established fences, or issue new first-use authority. Assignment/context files, per-target management journals, and USB/UDP logging policies retain their independent owners under the admitted generation. Their migration captures hashes and bounded descriptors, streams 64 KiB chunks, and validates actual owner recovery before publication. Management journals remain bounded at 16 MiB each and 96 targets; their bodies are not accumulated into a single Pi 1 memory image. The SQL catalog supplies management-history authority directly and never probes a missing file-backed catalog path.

## IPC and process contract

The ordinary Pi backend remains hybrid. The existing explicit controller-only runtime selects no local output. A dedicated artifact with no compiled physical or simulated backends remains part of #475, whose missing build/platform profiles are not implemented or qualified here. Early entry-point dispatch selects backend, web, CLI or narrow maintenance work before hardware/identity initialization. One backend owns live catalog, native settings, device connections, browser authorization authority and support jobs. HTTP and browser WebSockets run in the web process behind the existing Apache/PHP assets. Device-to-device listeners remain with backend crypto authority.

Local protocol version 1 has closed operation names and typed request/response/event documents; no SQL, arbitrary path, serialized principal or caller-authorized boolean is accepted. Bind requests to verified OS peers, boot/connection identity, current request origin/session and the operation's existing revision/authorization preconditions. Derive payload limits from current production routes. Control and bounded bulk/event paths cannot block the RF execution thread. Unix sockets cover Linux/macOS; local-only ACL-restricted named pipes require the accepted Windows adapter. Unsupported adapters refuse operation rather than using TCP.

A trusted listener descriptor provides the web service's ports and verified host identity without giving it database access. An admitted restore retains its maintenance listener descriptor and job authority outside replaced state until outcome readback. The installed worker has fixed state roots and service operations; it is not a second live backend or a general shell interface.

The Linux browser unit runs as `www-data` with a private listener cache under `/var/lib/wsprrypi-web`; the backend remains root with group-accessible IPC under `/run/wsprrypi`. The unit uses `Wants`/`After` without propagating backend stops. Installer fixtures cover both services, `--no-web`, failed starts, rollback, and uninstall ordering. Backend teardown drains all local request workers before stopping their domain owners. Actual-process fixtures exercise separate HTTP/WebSocket listeners, origin/session refusal, connection-owned tone cleanup, backend exit with retained web endpoints, and truthful backend-unavailable responses. Tone reservation/cleanup uses the established execution-suppression seam; actual simulated autonomous scheduling is exercised separately with both web services and the controller absent.

Current selected companion software uses Pico revision `7c09ff0fb15bb421f9010fb6faa6868f61b7a1a4` and MbedTLS revision `0bebf8b8c7f07abe3571ded48a11aa907a1ffb20`. The open sibling Pico checkout remains unchanged; a temporary checkout of the Pi contract's recorded source pin supplies the tests. The actual network runtime/configuration and USB management pairs pass against that selection. Shared Setup browser checks preserve native/Pico drafts, isolated target writes, fresh-context recovery, and autonomous remote jobs at desktop/mobile sizes in both themes. The actual Linux split-process fixture also runs the frontend as `www-data` and verifies kernel refusal of private SQLite reads while HTTP/WebSocket requests succeed. Backend-down and cached frontend restart remain available with truthful errors. These are software checks, not installed-service, physical USB, or RF qualification.

## Backup format and resource contract

Use one versioned encrypted recovery archive for CLI and Maintenance. The inner manifest names only approved records/files and records source role, identity, application/storage versions, bounded sizes and digests. Capture a SQLite snapshot and independently owned companion records under a coherent mutation barrier. Never infer multi-store consistency from a successful database backup alone. The restore purpose selects permitted destination application; it does not change archive encoding or discard recovery credentials at backup time.

The selected outer format is age version 1 with maintained age v1.3.2 and a pinned Go 1.27.4 helper. The helper fixes scrypt work factor 15 (approximately 32 MiB), admits one bounded scrypt header before decoding, limits streamed archive bytes to 2 GiB, and receives a bounded passphrase frame through descriptor 3. Module/toolchain checksums freeze its dependency inputs. Stock age can decrypt its output; higher-cost or other-recipient age files are outside the application recovery profile. Passphrases never enter argv, environment variables, logs, or staging files. Authenticated encryption success alone does not establish archive inventory or multi-owner consistency. The helper, bounded archive engine, actual-owner capture, independent maintenance broker, browser download, and nonmutating restore preview are implemented. Confirmed restore, CLI/Maintenance workflows, retained generations and evidence, worker packaging, and separate local/remote destination-review holds use this engine. See the [upstream release](https://github.com/FiloSottile/age/releases/tag/v1.3.2) and [application recovery contract](../../src/application_recovery/README.md).

Bound one admitted backup/restore mutation at a time; apply current job ownership/retention patterns to completed archives and remove incomplete files. Stream encrypted bytes and reject unsafe members, excess expansion, unexpected files and unsupported formats before mutation. Preserve pending/unknown operation evidence without replay. Restore is a new maintenance decision with protected pre-restore state and durable generation selection, a fresh boot/session context and a new persistent output hold. Reconcile pairing against current authority or require existing pairing recovery. A copied old backup never becomes permission to execute or reauthorize a revoked peer.

## Diagnostics and platform boundary

The administrator-only `--diagnostic-export` reads supported settings through the running backend. It re-encodes the closed current configuration and advanced registry, never raw SQL or opaque owner records. Bounded chunk responses bind the complete export digest; concurrent changes or unavailable ownership return an unavailable document without partial settings. Storage format/revision/hold, backend build, selected role, and admitted active HTTP/WebSocket ports are separate from saved listener values. The support collector includes this export only when configuration collection is enabled and otherwise retains metadata. Backend outage still permits independent host, service, and log observations; ports and settings remain explicitly unavailable. Private key stores, raw databases, retired source INIs, decrypted staging, and inactive recovery evidence are excluded. Existing readable-candidate, encryption, download-consent, and private-intake ownership remain unchanged.

Linux service templates and POSIX/macOS software fixtures do not implement a Windows named-pipe, ACL, service, or native hosting adapter. Issue #475 must qualify each accepted native profile using the SQLite owner, separated frontend, and bounded independent maintenance lifecycle; it must not reintroduce live INI storage or merge browser privileges into the backend. The normal Pi role remains hybrid, with local output and permitted remote management together. Controller-only remains an explicit zero-output role, never a fallback after hardware failure.

## Initialization, commands, and recovery

The installer performs explicit state admission before starting the backend. For isolated development, `wsprrypi --initialize-state --state-directory /absolute/private/root` provisions fresh state, and `wsprrypi --migrate-state --state-directory /absolute/private/root --ini-source /absolute/existing.ini` imports an existing installation. Supply `--controller-only` for that role. These commands do not start transmission. Do not use fresh initialization to repair lost established state or delete an authority marker to force admission. `--check-state` validates the selected role/generation without repairing it. Retain the original `.sqlite-migrated` input and protected earlier generations for recovery; neither is an ongoing settings source.

Use the existing UI for ordinary settings and `sudo wsprrypi --settings read` followed by one revision-bound `--settings write` for advanced values. Advanced native fields are `Meta.debug_logging`, `Operation.Web Port`, `Operation.Socket Port`, `Experimental.Allow Unqualified Frequency`, `Experimental.Allow Non-Amateur Frequency`, `Si5351.TX Output`, and the four CW fade settings. A controller exposes debug logging and listener ports only. Private network policy keeps its existing management workflow. Saved loop/iteration preferences remain distinct from changing execution counters. Saved ports may differ from explicit active startup overrides.

Maintenance creates and downloads an encrypted archive, uploads an existing archive, validates a recover-or-move preview without replacing active state, and requires explicit confirmation of the current preview digest. Retain the passphrase separately; it cannot be recovered from the archive. The local `--maintenance` commands use the same engine when the browser is unavailable. See the [command reference and recovery limits](../../src/application_recovery/README.md). Backups are per installation and do not back up or stop remote devices.

After confirmation, durable job status belongs to the independent maintenance worker. Read that status after connection loss instead of submitting another restore. A failed restart or proxy update leaves the selected state held, with protected earlier generations and explicit resume where supported. A new generation does not resume queued work, adopt remote schedules, reset destination identity, or activate source credentials. Review the actual destination wiring, calibration, connection definitions, and authority before releasing the separate local and remote holds. Local release leaves output stopped; starting output remains an explicit existing operator action. Corrupt established destination state that cannot pass owner validation remains an explicit recovery requirement rather than an automatic empty installation.

## Interrupted initial admission

The installer invokes `--check-state` for an existing root and never falls back to initialization or INI reimport after refusal. An interrupted first migration/initialization therefore requires the administrator to repeat its original explicit `--migrate-state` or `--initialize-state` command with the same role and absolute paths while the backend is stopped, then rerun installation. Migration resumes its admitted snapshot after source retirement; retain the original source path even when only its `.sqlite-migrated` backup remains. Source/context mismatch, corrupt established state, and confirmed restore recovery remain separate refusals or owning recovery operations. Do not remove the root or staging to force fresh admission.
