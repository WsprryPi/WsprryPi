# BCM2835 GPIO qualification owner

The separately built Linux command `wsprrypi-gpio-qualification-owner` owns a conducted qualification run on a Raspberry Pi Model A+ with BCM2835. A one-shot authenticated SSH invocation passes one bounded, closed JSON request on standard input. Runtime uses two separate authenticated invocations of the fixed `--runtime-stream` mode. Each stream carries one compact JSON request per line and one matching reply, with a single request outstanding per connection. Each response echoes the contract `wsprrypi.gpio-qualification-owner.v1`, operation, unique call nonce, and SHA-256 of the request bytes. The owner uses a private local supervisor and launches one disposable worker for each of the eight drive groups. The worker channel is a connected IPv4 loopback pair with no listening socket during the group.

## Admission and evidence

Each run selects GPIO4/ALT0 or GPIO20/ALT5 for GPCLK0. The other route stays in input mode. Both routes share a cooperative lease on GPCLK0, the GPIO0–27 pad bank, PWM, and DMA channel 0. Ordinary BCM2835 preparation and startup quiescence on this board honor the same lease and recovery record. Direct register writers, the kernel, and older WsprryPi binaries do not participate in the lease.

Read-only Review checks the entire ordered matrix in one owner invocation. Source observations before and after native admission bind the plans to the board, boot, artifact, station state, normal service, and explicit correction selection. Review reads no MMIO and starts no worker. Its three-second owner budget reserves one second per source observation and one second for matrix planning and source reads. On `wspr1`, the measured service query took 337–414 ms. The one-second Review observation budget rounds the maximum up to 500 ms and reserves another 500 ms for variability. Runtime uses the separately bounded service checks.

The selection file `clock.json` in the private owner directory contains `policy` (`uncalibrated` or `selected`), signed integer `ppm_millionths`, and `provenance`. An uncalibrated selection supplies zero additional correction. Admission still composes the BCM2835 intrinsic correction. It evaluates the ten exact carriers from 475,700 Hz through 28,126,100 Hz at each nominal drive setting from 2 through 16 mA. Native divider refusal preserves the requested carrier and correction. The claimed run checks the whole matrix before the meter workflow begins. Reserve and the native worker independently recalculate the same exact plan before enabling.

For each admitted point, the divider planner produces two adjacent 12.12 words. The worker programs an immutable 4,096-sample DMA ring divided into 64 blocks, with the integer duty allocated by the shared native dither arithmetic. The reported bounds cover a modeled time-weighted mean over any uninterrupted window of at least one second after the PWM FIFO and ring settle. The calculation allows for partial blocks at both ends and rounds outward to integer nanohertz. The bounds depend on the selected clock model and orderly PWM pacing. The individual divider frequencies, measured oscillator accuracy, instantaneous RF, fixture response, and HP meter integration behavior require separate evidence. ## Owner lifecycle

| Operation | Scope |
| --- | --- |
| `review_matrix` | Read-only ordered 80-point matrix with source observations bracketing native admission. |
| `review`, `admit` | Read-only identity and single-point planning for runtime validation. |
| `claim`, `admit_matrix` | Freeze the route and original bank under the device lease and durable run record, then recompute the matrix. |
| `open_group`, `close_group` | Start and retire the identified loopback worker for one drive group. Closure requires native idle readback, the original bank, and verified worker exit. |
| `reserve`, `start` | Issue a short-lived generation before Start. Recheck the exact plan, station, and service, then arm the worker and supervisor with a Pi-monotonic reference before enabling. |
| `status`, `stop` | Address the exact run, route, worker, request, and generation. A Stop recorded while reserved fences delayed Start. Active status requires native route, clock, divider, drive, and DMA readback. Terminal status requires native shutdown evidence. |
| `lookup`, `release` | Resolve lost replies by original identifiers. Release records retrievable terminal evidence before clearing the recovery duty. |

The cutoff is 50,000 ms from a conservative pre-enable timestamp. The worker and supervisor begin cutoff cleanup 1,500 ms before that ceiling. The worker also reacts to private-channel loss. Claim, matrix admission, group preparation, Reserve, and Start each require a fresh synchronous source observation. During supervision it begins a bounded service probe 200 ms after the last successful probe and consumes its result without waiting in the Status or Stop handler. The probe budget is one second. The measured maximum service query on `wspr1` was 480 ms, rounded to 500 ms with another 500 ms reserved for variability. A failed or expired probe inhibits the run and invokes owned shutdown. The supervisor can retire a stalled worker before attempting owned cleanup. Native cleanup checks GPCLK enable and busy, the DMA and PWM resources, both pins, and the pad bank. Drive changes preserve hysteresis and slew. An external pad change is left in place, and uncertain shutdown, worker exit, or restoration leaves a durable recovery hold. A hold blocks later runs across a reboot. Reconciliation requires fresh evidence from the exact board and boot before the hold may be cleared.

## Provisioning and physical gates

Build the separate owner with `make -C src gpio-qualification-owner`. Provision its root-owned private directory at `/var/lib/wsprrypi/gpio-qualification` and the fixed command at `/usr/local/libexec/wsprrypi-gpio-qualification-owner` only during an authorized installation. The SSH authorization must restrict the bench principal to this exact input-only command and effective privilege. Deploy the matching WsprryPi binary with cooperative lease enforcement before a native claim. Keep the board service inactive, disabled, and PID zero, and exclude other writers to the selected pins and shared resources. The owner never changes service state.

RF-free live Review must verify the exact board, executable hash, correction and provenance, unchanged station settings, all 80 admissions, and the actual SSH response budget. Separate qualification establishes idle-resource and pin readback, effective privilege, timing, cleanup, restoration, and independent bench shutdown before a supervised conducted run. Software cutoff depends on the ability of the Pi processes and OS to execute. A stall that prevents both processes from executing requires independent bench shutdown. The historical 475,700 Hz, 2 mA GPIO20 observation qualifies only that recorded setup.
