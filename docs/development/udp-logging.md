# UDP logging

The [Pico UDP logging contract](https://github.com/WsprryPi/WsprryPico/blob/devel/engineering/development/udp-logging.md) defines the shared wire profile, resource boundaries and [source-bound validation applicability](https://github.com/WsprryPi/WsprryPico/blob/devel/engineering/development/udp-logging.md#validation-and-applicability). Pi-specific worker, service and UI behavior is described below. Operator instructions are maintained in the [Pi Logs guide](https://wsprry-pi.readthedocs.io/en/devel/User_Interface/Logs/index.html).

`src/udp_logging` owns strict host policy, portable wire validation, selected-member negotiation and the separate unprivileged worker. The first-party UI remains tracked parent content. Native producer records carry a separate fixed-template export projection; unknown messages and arbitrary MESSAGE content are excluded. Physically checked USB records require both the saved collection policy and an exact selected Fleet profile/device pair. UDP journal imports and worker diagnostics cannot forward.

The worker executable is built separately and embedded in the verified parent executable. `--export-udp-logging-worker` extracts that exact image before application or hardware startup. The installer compares the extracted image, installs `wsprrypi-log` and a static-user unit, and leaves logging disabled unless an existing valid policy explicitly enables it. Older precompiled images without the embedded worker leave disabled policies unavailable and refuse an enabled policy. Removal disables the managed service/socket and preserves the policy. Unmanaged unit files and symlinks are refused.

The service has no device access, transmitter IPC or capabilities. It uses IPv4 ioctls to enumerate interfaces within its AF_INET/AF_UNIX restriction. The supplementary systemd-journal group permits broad host-journal reads; the worker immediately narrows its reader to the real transmitter unit and independently verifies every eligible record's origin, collector and ingress. The UI does not receive that group membership. Its own real journal unit stores imports without fabricated underscore fields.

Port 5514 binds one explicit interface IPv4. Port 514 uses a root-installed systemd datagram socket and an exact opaque policy-revision environment binding; the unprivileged worker refuses a stale socket generation. New destination, interface and bind policies are validated before service changes. A concurrent interface or port change can still make application fail; saved and active policy remain separate and the UI requires authoritative readback after an uncertain result. No firewall opening, logging-stack replacement or global retention change is performed.

The exact host policy and API shapes are in `docs/schemas/host-udp-logging-1.schema.json`. Independent `GET /api/v1/host/udp-logging/installation` uses `host-udp-installation/1` to report missing/unsafe/installed worker, valid/invalid/unavailable policy and inactive/running/bind-error/ready service without adding fields to the closed settings response. Independent finite test discovery and requests use `udp-logging-test-capabilities/1` and `udp-logging-test/1`; the native test event is an explicitly allowlisted `PI_LOG` template. Settings, wire, test, installation and USB contracts retain independent versions.

Logs explicitly selects stream version 2, with a fixed OR of the real transmitter and logging units and the existing verified manager rule. Missing remote origin fields do not inherit local host identity. UDP source menus use only configured peers and bounded observed origin history. Source cursor keys include verified collector, stream, replay, source/peer address, ingress and severity. A peer binding change resets only the affected view context. All retains bounded historical records beyond the selectable source menu.

Run `make -C src udp-logging-worker udp-logging-test SUDO=` and `python3 -B scripts/tests/udp_log_control_test.py` for worker/policy checks. UI checks include `node WsprryPi-UI/tests/udp_logging_settings_test.js`, `php WsprryPi-UI/tests/log_origin_v2_test.php` and `node WsprryPi-UI/tests/udp_logging_ui_integration_test.js PATH_TO_ACTUAL_PICO OUTPUT_DIRECTORY`. These supplement the checked-in network and USB production-pair recipes; they do not replace either pair or qualify physical installation, USB/network transport, timing or RF.

The Logs replay/source regression renders the actual page with `(cd WsprryPi-UI/data && php -r '$_GET["page"]="logs";include "index.php";') > /tmp/udp-logs-rendered.html`, then runs `LOGGING_RENDERED_HTML=/tmp/udp-logs-rendered.html node WsprryPi-UI/tests/udp_logging_logs_browser_test.js`. It deliberately delays peer discovery until after SSE replay and checks stable IDs, separate direct/relay selections and safe rendering.

The worker requires enforceable memory and PID cgroup controllers. The managed unit uses `ConditionControlGroupController=memory pids`; the worker independently verifies its own 32 MiB memory and two-task limits in the v1 or v2 hierarchy and refuses root execution or unbounded limits. Enabling a host policy is refused before writes when the controllers are unavailable. The installer does not change kernel boot options. Some Raspberry Pi kernel configurations disable memory accounting; host setup must be deliberate and verified after reboot, using the [Raspberry Pi kernel memory-controller discussion](https://github.com/raspberrypi/linux/issues/6980) for context. `MemoryMax` text in a unit file alone is not proof that the limit is enforced.

Policy application and disabled export advance the journal reader to the current tail; enabling export does not replay records generated while it was disabled. Journal invalidation is handled before reading entries, increments the discontinuity counter and resumes at the current tail. A changed worker image or managed unit is restarted on installation; unchanged policy saves use bounded reload without an unnecessary restart.

## Clock events and viewer continuation

Pico `CLOCK_STATE` exports distinguish `UTC synchronized`, `UTC holdover`, and `UTC unavailable`. First usable time and restoration are Info (6), ordinary synchronized/holdover transitions are Debug (7), and loss of usable time is Warning (4). Both producer-template copies retain historical `UTC available` admission and add the two precise usable-state templates. The existing wire schemas permit bounded message strings and severity 0–7; their fields, limits and historical validation are unchanged.

The Logs page loads bounded recent history for a new source/severity context or page load. Reconnect and Resume view continue an unchanged retained view; Clear preserves that continuation point. The network CI job exercises the production JavaScript and PHP stream adapter with deterministic journal input through `LOGGING_REAL_STREAM=1 LOGGING_RENDERED_HTML=/tmp/udp-logs-rendered.html node tests/usb_logging_browser_test.js` from `WsprryPi-UI`. The private fixture reads no system journal and exercises cursor-at-tail, invalid cursor, filtering and child cleanup through the actual adapter.
