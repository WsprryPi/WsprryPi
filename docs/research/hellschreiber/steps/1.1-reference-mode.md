# Step 1.1 — Define the reference mode

## Status

Complete for documentary research. No implementation, signal generation, hardware operation, or over-the-air testing was performed.

## Executive conclusion

Use **standard Feld-Hell at 122.5 baud** as the reference baseline for later Hellschreiber comparisons. This is a research baseline, not a Wsprry Pi implementation decision.

The historical contract is unusually well supported. The 1941 German Army manual specifies 2.5 characters per second, seven columns per character, a shortest keyed interval of about 8.16 ms, and 122.5 baud. It also describes bottom-to-top scanning within each column, left-to-right column order, unsynchronized continuous operation, and the receiver's two-turn spindle that prints every transmitted character twice. Current fldigi, Wavecom, MultiPSK, and RadioLib materials independently reproduce the important timing and raster behavior.

The apparent disagreement between **7x7 at 122.5 baud** and **7x14 at 245 pixels/s** is representational, not a different on-air mode. A logical 7x7 cell lasts 8.163 ms. Some software expands each logical row into two identical 4.082 ms raster samples, yielding 14 samples per column and 245 samples/s, but those samples occur in constrained identical pairs. They do not constitute 245 independent binary symbols per second.

Step 1.1 does not freeze an exact glyph set, pulse shape, audio tone, receiver filter, or occupied-bandwidth number. Those are common compatible conventions or later research decisions rather than the minimum historical interoperability contract.

## Research question

What historical and on-air contract should define the standard Feld-Hell reference baseline against which later Hellschreiber modes, fonts, adoption evidence, interoperability tests, and Wsprry Pi feasibility are compared?

## Scope and boundaries

This step:

- identifies the reference machine and mode;
- reconstructs its raster, scan order, timing, modulation, synchronization, and receive presentation;
- reconciles historical terminology with modern software representations;
- separates normative behavior from common conventions and implementation choices.

This step does not:

- select a production mode or font for Wsprry Pi;
- define the complete Hellschreiber mode taxonomy;
- measure current amateur-radio adoption;
- perform interoperability, audio, RF, GPIO, or hardware experiments;
- modify application code, UI, configuration, scheduling, services, submodules, or operator documentation.

## Method

The baseline was reconstructed from the 1941 field manual, then checked against a university collection, an identified historical reconstruction, current official software documentation and source, and independent decoder/transmitter implementations. Numerical quantities were recomputed from the primary manual rather than copied from secondary summaries. Conflicts were retained when they reflected different definitions or measurement layers.

## Reference machine and mode

The reference is the Siemens & Halske **Feldfernschreiber**, commonly called Feld-Hell and identified in the historical reconstruction as the **T.typ.58** (military designation Tbs 24a-32). It was a keyboard-operated facsimile teleprinter associated with Rudolf Hell's printing-telegraph system. The 1941 manual calls the apparatus a field teleprinter and states that the earlier name *Typenbildschreiber* was replaced in use by *Hellschreiber* after its inventor.

The manual establishes the operational baseline directly: 150 characters/minute, 2.5 characters/second, seven columns per character, and 122.5 baud. It describes operation over a telephone circuit or radio link using keyed 900 Hz audio. [HELL-EVID-0001]

Patent evidence establishes the earlier technical lineage but is not used to infer the field machine's later numerical contract. The core German patent is DE540849; DE541935 is a related addition, not a substitute specification for the T.typ.58. [HELL-EVID-0002]

## Terminology used in this report

| Term | Meaning here |
| --- | --- |
| Logical cell | One independently mark-or-space raster interval in the historical 7x7 character cell; 8.163 ms at the reference rate. |
| Elementary raster sample | One half of a logical cell in a modern 7x14 representation; 4.082 ms and constrained to match its paired sample. |
| Column | Seven logical cells scanned bottom-to-top; 57.143 ms. |
| Character cell | Seven columns: normally five image-bearing columns plus two columns of inter-character space; 400 ms. |
| Baud | Independent signaling intervals per second. The historical and preferred reference value is 122.5 baud. |
| Pixel | Avoided without qualification because sources use it for both logical cells and duplicated elementary samples. |
| Double printing | Receiver presentation of two vertically displaced copies from a two-turn spindle; it is not transmission of the character twice. |

## Historical reconstruction

The 1941 manual describes a 43-key, uppercase keyboard: 26 letters, digits 0–9, four punctuation characters (`+`, `-`, `/`, `?`), a blank/space key, a pause key, and a Morse key. Pressing a character couples its coded drum to the continuously driven shaft for one revolution. The mechanical lockout fixes each character at 0.4 seconds. [HELL-EVID-0001]

Each coded drum divides a character position into seven columns. Five columns carry the letter image and two supply spacing. In each column the contact trace is read from bottom to top, and columns proceed left to right. The minimum mark or space is one seventh of a column height. The transmitter drum turns 2.5 times/second, so it produces 17.5 columns/second and 122.5 independently keyable raster intervals/second. [HELL-EVID-0001]

The receiver is deliberately asynchronous. Its helical spindle has two turns and prints two copies of the character, one above the other, on moving paper tape. Exact transmitter-to-receiver phase is therefore unnecessary; a vertical phase boundary may split one copy while leaving the other readable. A speed mismatch makes the text slope rather than causing a digital framing failure. [HELL-EVID-0001] [HELL-EVID-0003]

## Raster and scan order

The logical character cell is traversed column-major:

```text
transmit c0 bottom→top, then c1 bottom→top, ... then c6 bottom→top

             column order →
top r6       c0 c1 c2 c3 c4 c5 c6
    r5       c0 c1 c2 c3 c4 c5 c6
    r4       c0 c1 c2 c3 c4 c5 c6
    r3       c0 c1 c2 c3 c4 c5 c6
    r2       c0 c1 c2 c3 c4 c5 c6
    r1       c0 c1 c2 c3 c4 c5 c6
bottom r0    c0 c1 c2 c3 c4 c5 c6
             ↑ each column is scanned r0 to r6
```

The following normalized uppercase `E` illustrates the traversal. It documents the encoding method, not a frozen historical drum font; Step 3 must determine the exact reference glyph evidence.

```text
             c0 c1 c2 c3 c4 c5 c6
r6 (top)      .  #  #  #  #  #  .
r5            .  #  .  .  .  .  .
r4            .  #  .  .  .  .  .
r3            .  #  #  #  #  .  .
r2            .  #  .  .  .  .  .
r1            .  #  .  .  .  .  .
r0 (bottom)   .  #  #  #  #  #  .
```

With `0=space`, `1=mark`, and each column listed bottom-to-top, this illustrative glyph becomes:

```text
c0 0000000
c1 1111111
c2 1001001
c3 1001001
c4 1001001
c5 1000001
c6 0000000
```

The on-air logical sequence is the concatenation `c0 || c1 || ... || c6`, for 49 logical cells and 400 ms total.

## The 7x7 / 7x14 and 122.5 / 245 reconciliation

The field machine's independently keyable geometry is 7x7. A modern sampled generator may represent every logical row twice:

```text
one logical column:       r0 r1 r2 r3 r4 r5 r6
7x14 representation:     r0 r0 r1 r1 r2 r2 r3 r3 r4 r4 r5 r5 r6 r6
duration per item:        8.163 ms logical; 4.082 ms per duplicated sample
```

Thus:

- `7 rows/column x 17.5 columns/s = 122.5 logical cells/s`;
- `14 samples/column x 17.5 columns/s = 245 elementary samples/s`;
- every adjacent sample pair is constrained to the same mark/space value;
- therefore the independent signaling rate remains 122.5 baud.

fldigi makes this relationship inspectable: it uses 14 transmitted raster samples per column at 17.5 columns/s, while its 7x7 font expands rows in identical pairs. Wavecom likewise describes 7x14 lines with pixels occurring in pairs. RadioLib instead emits the 49 logical 7x7 cells directly at the default 122.5 rate. These are compatible representations of the same baseline. [HELL-EVID-0005] [HELL-EVID-0006] [HELL-EVID-0007] [HELL-EVID-0009]

MultiPSK's phrase “245 bauds but in fact pseudo-122.5” mixes the elementary sampling rate with the effective signaling rate. Its stated 8.163 ms pixel duration supports 122.5 logical intervals/s. This report uses 245 **samples/s**, not 245 baud, for that doubled representation. [HELL-EVID-0008]

## Timing reconstruction

Starting with the manual's 2.5 characters/s:

```text
character duration       = 1 / 2.5                 = 0.400000 s
column rate              = 2.5 x 7                 = 17.5 columns/s
column duration          = 1 / 17.5                = 0.0571429 s
logical signaling rate   = 17.5 x 7                = 122.5 baud
logical cell duration    = 1 / 122.5               = 0.00816327 s
7x14 sample rate         = 17.5 x 14               = 245 samples/s
elementary sample time   = 1 / 245                 = 0.00408163 s
```

The manual's 150 characters/minute also explains the customary **25 WPM** figure when one word is counted as five characters plus a following space: `150 / 6 = 25`. A five-character convention without the space would produce 30 WPM, so WPM should not replace the unambiguous 2.5 characters/s value.

For an alternating logical mark/space pattern, a complete cycle is two logical cells:

```text
keying fundamental = 1 / (2 x 8.16327 ms) = 61.25 Hz
```

That value is a maximum alternating-pattern fundamental, not a complete occupied-bandwidth specification.

## Logical modulation

The minimum reference behavior is binary on/off keying of a carrier or audio subcarrier according to the raster. The historical machine keyed an approximately 900 Hz audio generator for carriage over telephone or radio circuits. Modern software commonly emits an audio tone with the same mark/space envelope and can be used with either sideband because the information is in the envelope rather than an audio-frequency shift. [HELL-EVID-0001] [HELL-EVID-0005] [HELL-EVID-0008]

The historical 900 Hz tone is equipment-specific. A particular modern audio pitch, RF sideband, amplitude, phase continuity, or transmitter interface is not part of the Step 1.1 baseline.

## Framing and synchronization

Standard Feld-Hell has no per-character start bit, stop bit, clock recovery field, or transmitted vertical-phase marker. Timing is continuous. The mechanical transmitter enforces fixed 400 ms character cells; even a blank character consumes its interval. The receiver runs at approximately the same nominal speed but need not share phase with the transmitter. [HELL-EVID-0001]

Consequences for later interoperability tests include:

- a decoder should tolerate arbitrary vertical phase at acquisition;
- clock mismatch should appear primarily as slanted or drifting text;
- blank spacing must preserve time even when no carrier is keyed;
- a software generator must not compress blank columns or characters;
- receiver presentation and glyph recognition matter more than byte framing.

## Receiver double printing

The historical two-turn spindle prints two copies vertically while the transmitter sends one raster sequence. This distinction is essential:

```text
transmitter:  one 7x7 logical character raster
receiver:     the same received raster traced by a two-turn helix
paper result: two vertically offset copies, with the tape boundary crossing at most one
```

Modern waterfall decoders may reproduce the same tolerance by displaying enough vertical extent for repeated raster phase, but a transmitter must not send each character twice merely to imitate the printed appearance. [HELL-EVID-0001] [HELL-EVID-0007]

## Character repertoire

The historical machine is uppercase-only and has a limited keyboard repertoire. Modern software often maps a larger printable character set into implementation-specific fonts. That extension can be useful between matching software endpoints, but it is not historical Feld-Hell interoperability evidence. [HELL-EVID-0001] [HELL-EVID-0006] [HELL-EVID-0008]

For the reference baseline, uppercase Latin letters, digits, space, and the historically identified punctuation are established. Exact glyph bitmaps and any additional printable characters remain Step 3 work.

## Pulse shaping and bandwidth

The manual establishes keyed tone behavior but does not supply a modern occupied-bandwidth mask. Contemporary implementations differ in pulse shaping and in how they quote bandwidth:

- fldigi offers square or raised-cosine edges and documents customary 4 ms HF and 2 ms VHF shaping;
- MultiPSK describes raised-cosine shaping and approximately 300 Hz;
- fldigi operating material quotes approximately 350 Hz;
- a 2025 measured analysis distinguishes the 61.25 Hz keying fundamental from sidebands and concludes that a well-shaped Feld-Hell signal fits within about 200 Hz under its test conditions.

These figures are not necessarily contradictory: fundamental frequency, transmitter sampling bandwidth, receiver filter width, and occupied emission are different quantities. [HELL-EVID-0005] [HELL-EVID-0008] [HELL-EVID-0010]

Step 1.1 therefore requires preservation of 8.163 ms logical cells and binary mark/space behavior, but does not prescribe a pulse-shaping function or a single bandwidth number. Spectral design and offline measurement must be evaluated before any implementation recommendation.

## Provisional normative contract for later research

Later spike steps should use the following testable contract when they say “standard Feld-Hell”:

1. A character occupies exactly 400 ms, or 2.5 characters/s.
2. Its timing cell is seven columns by seven independently keyed logical rows: 49 logical intervals.
3. Columns proceed left-to-right; cells within a column proceed bottom-to-top.
4. Each logical cell lasts `1 / 122.5` seconds, approximately 8.163 ms.
5. Mark/space state controls an on/off carrier or tone envelope; blank cells still consume time.
6. The stream has no per-character start/stop framing and no transmitted raster-phase synchronization.
7. Historical receive double printing is a receiver presentation technique, not duplicate character transmission.
8. A 7x14, 245-sample/s generator is equivalent only when every adjacent vertical sample pair represents one 8.163 ms logical state and total timing is unchanged.
9. Uppercase historical repertoire is the conservative compatibility baseline; exact glyph bitmaps are not yet frozen.

This contract is accepted as the spike's comparison baseline. It does not authorize implementation and may be refined only through an explicit later decision with evidence.

## Common compatible conventions

The following are well-attested modern practices but are not required by the minimum reference contract:

- a 7x14 internal raster with duplicated samples;
- raised-cosine keying edges;
- approximately 2 ms or 4 ms edge-shaping selections;
- audio-tone generation suitable for SSB transmission;
- waterfall display instead of paper tape;
- extended printable-ASCII glyph sets;
- receiver bandwidths in the broad 200–350 Hz range, depending on definition and conditions.

## Non-normative implementation choices

The spike has not selected:

- exact font bitmaps or a modern font index;
- audio pitch, sample rate, output amplitude, or sideband;
- pulse-shaping curve or transition duration;
- occupied-bandwidth target or receiver filter;
- leading/trailing idle duration, message preamble, or operator formatting;
- Unicode/transliteration behavior;
- transmitter, decoder, scheduler, UI, CLI, configuration, or GPIO architecture.

In particular, fldigi's current default font and shaping settings document fldigi, not the historical Feld-Hell standard.

## Contradictions and unresolved questions

- The exact original drum glyph matrix must be recovered and compared with common fldigi/G3PLX and other amateur fonts in Step 3.
- The mapping and shapes for the historical punctuation, space, and pause functions need font-level evidence.
- A future offline test should prove that direct 7x7/122.5 and paired 7x14/245 representations produce equivalent envelopes after resampling.
- Pulse-shaping and occupied-bandwidth claims require a common measurement definition and offline spectra before a Wsprry Pi recommendation.
- Current amateur usage and software interoperability cannot be inferred from implementation availability; Steps 4 and 5 must supply adoption and experimental evidence.
- Historical motor tolerance is documented, but acceptable software clock error and decoder acquisition behavior require measurement.
