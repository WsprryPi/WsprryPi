# Application recovery

This application-private directory implements the shared encrypted recovery engine used by local maintenance commands and the Maintenance page. The backend captures and validates persistent owners. An independent maintenance worker owns encrypted archives, durable jobs, stopped-backend generation replacement, and verified restart. The browser process proxies bounded requests and encrypted downloads without database, credential-store, or lifecycle privileges.

The encryption adapter pins age v1.3.2 and Go 1.27.4, with module checksums in `age_helper/go.sum` and toolchain checksums in `scripts/recovery_age_provider.json`. It emits interoperable age version 1 files using one scrypt recipient with work factor 15 (`N=32768`, `r=8`, and `p=1`, approximately 32 MiB for derivation). The parser admits only this bounded recovery profile before running the maintained age decoder. Stock age can decrypt these files; arbitrary age recipient types or higher-cost passphrase files are outside this recovery format. Use a strong, unique passphrase and retain it separately from the archive.

Passphrases enter the helper through a bounded pipe on descriptor 3, never arguments, environment variables, logs, or files. Archive bytes stream through standard input/output with a 2 GiB bound and 64 KiB copy buffers. The helper can emit partial staging bytes before a final authentication or I/O error; only a successful owning archive job may publish its output. A decoder's successful header check is not archive validation. Go retains temporary managed-memory copies of secrets; no claim of complete heap zeroization is made.

The helper contains maintained BSD-licensed dependencies alongside MIT-licensed WsprryPi integration code. Preserve their notices when packaging. The source/build checks do not qualify Pi memory use, SD-card performance, installed services, or RF behavior.

Capture pins the actual pairing/key-history and Fleet retirement owners and fences companion observations around a SQLite-consistent read cut. It streams per-target journals rather than collecting them into one memory image. Native capture refuses armed local transmission, active occurrences, Test Tone ownership, unknown cleanup, or unavailable owner admission; it never stops output to obtain a snapshot. Controller capture has no local-output requirement. Encryption runs after the private snapshot is complete. Staging-space checks use the database's current logical page count and included file sizes.

The maintenance worker's internal `recovery.capture` operation accepts only an admitted job ID through the administrator-only backend socket. Job paths derive from the fixed private maintenance root. Admission binds the exact backend boot and installation identity. A terminal capture proof is published once outside the application generation, and a lost reply never causes automatic recapture. Browser-process peers cannot invoke this operation directly.

Focused software checks run from `src`:

```sh
make recovery-age-unit-test recovery-archive-test recovery-capture-backend-test sqlite-state-store-test BACKENDS=simulated ANCILLARY_GPIO=0 SUDO=
```

`RECOVERY_AGE_GO` may explicitly select an already verified Go 1.27.4 toolchain for a local build. Otherwise, the builder downloads the host's checksum-pinned toolchain into ignored build output. This is build tooling, not a runtime Go installation. The helper is embedded in the application artifact for fixed-path installer extraction. The source builder uses string literals for the binary image to avoid millions of C++ initializer nodes on small build hosts.

The maintenance process runs as an explicit early application role and never opens the active SQLite database. It owns one isolated Python worker through bounded private pipes, a separate administrator socket, and a browser HTTP domain. Worker death poisons an outstanding request; it never restarts a mutation automatically. The worker process group contains only its owned query/encryption children and is killed and reaped at broker teardown. A private directory lock excludes duplicate maintenance owners before job recovery.

A recovery browser lease is issued only after the backend's existing management session authorizes an enforced local mutation. Its independent HttpOnly, SameSite=Strict cookie and CSRF value survive backend restart; only hashes are retained in the private lease file. The cookie uses the established management session's root path so it covers both direct hosting and the installed `/wsprrypi` alias. Every request repeats the existing current network, Host, Origin, and trusted-proxy guard. Job identifiers and encrypted archives do not authenticate a request. Reads do not renew leases or rewrite job state. The lease expires after 24 hours; source-generation replacement does not restore old browser sessions.

The job owner admits one active job and retains at most three prior terminal jobs. A pinned download prevents pruning its archive. Admission and pruning recover their durable crash windows without applying state or replaying a capture. Uploaded ciphertext arrives in bounded chunks; an exact duplicate chunk is idempotent, while a changed duplicate is rejected. Hashing and encryption run asynchronously. Validation binds the ciphertext to its original upload receipt. Wrong passphrases can be retried on the same upload, and an explicit operator validation can refresh an unconfirmed preview against current destination state. Refresh serializes with the actual validator before removing its previous private staging. A lost backend validation reply waits for its one immutable owner proof rather than issuing validation again.

Restore preview copies authenticated decoded members through bounded hash/stat checks into private validation staging. The actual SQL, native/controller settings, Fleet companions, pairing history, retirement fences, and configured credential validators run on those copies. The selected generation remains unchanged. Preview binds the archive, purpose, current backend boot, and a digest of the current destination SQL and companion-owner context. It lists concrete setting changes, retained destination settings, Fleet definitions, and old/new listener ports. The current portable adapter preserves destination GPIO, amplifier/LED/shutdown wiring, transmitter backend, calibration, Si5351 adapter/reference configuration, band GPIO, network safety, and experimental frequency policy; it carries station/signal settings, custom CW timing/fades, startup intent, debug logging, and listener ports. Roles cannot be converted by restore.

The actual three-process software fixture covers existing-session admission, CSRF refusal, coherent encrypted backup, range/download retry, continued downloads during backend outage, maintenance restart with the same browser lease, independent decryption, wrong-passphrase retry, nonmutating source-owner validation, exact confirmation, candidate construction through actual owners, retained prior generations, publication, verified held restart, changed HTTP/WebSocket ports, frontend restart, stale destination review, and separate hold release. The same fixture exercises the local CLI and existing controller-only role. The actual browser fixture covers create/download/upload/validate/confirm/reconnect, keyboard operation, failed readback, destination review, and desktop/mobile light/dark rendering. These are software checks, not installed systemd, Pi performance, or physical-output qualification.

Browser-fixture failures retain a bounded request/status timeline correlated with explicit validation attempts, public job state/error, and allowlisted owner validation-result fields in the test log before cleanup. A terminal rejection after the correct-passphrase attempt fails immediately instead of waiting for an unavailable preview. Diagnostics exclude passphrases, session credentials, archive contents, and private settings. Post-reload readiness waits for the replacement main document rather than accepting the outgoing page’s completed state. A passing local run does not establish the cause of a prior hosted failure.

Confirmed hold preparation records a pending selector decision in the application root before publishing its hold and selector. Normal open, initialization, and migration refuse that pending decision. The independent maintenance owner holds the same root lock, verifies the exact old/new observations, finishes both holds, and removes the pending marker before normal startup. The worker briefly retries an explicit busy refusal issued before hold publication. If the preparation reply is lost, the worker reads the durable stop proof for the admitted job and backend boot. Four actual child-process deaths cover these preparation boundaries; selected settings and receipts remain unchanged. Pairing final-publication admission, administrator settings writes, browser mutations, and outgoing management mutations respect the maintenance/remote holds. Confirmed jobs cannot be cancelled as unconfirmed uploads. Recovery resumes the same admitted data publication and never repeats capture, Stop admission, or a remote operation. Early preparation without positive drain proof reports an interrupted, held prior generation rather than fabricating successful cleanup.

Inactive reconciliation evidence uses closed `recovery-evidence/1` groups under the selected generation. Each group identifies the source installation and validated source records, lists bounded payload sizes and SHA-256 digests, and derives its directory name from the content digest. Source SQL records, pairing/key history, retirement fences, and management journals remain private evidence and are never loaded as destination settings, active credentials, receipts, or runnable commands. Existing groups copy unchanged and deduplicate by content. The archive's existing 1,024-member and 2 GiB limits apply to the combined inventory. Both Python and C++ validators reject unexpected files, malformed indexes, changed hashes, and symlinks. Snapshot capture includes these groups; diagnostics exclude their contents. The complete candidate starts from destination authority and receipts, applies supported settings and definitions through current owners, retains source evidence, and publishes only after closed inventory validation and durable synchronization. New engineering network definitions without destination credentials remain unresolved evidence; moved USB definitions require destination transport selection.

The selected generation has separate persistent local-output and remote-authority holds. Successful restore reports a historical `completed_held` result; it does not claim those holds are still current after operator review. A fresh destination review binds current settings, owner context, backend boot, and hold revision. Destination-context lock contention reports `409 busy` before a review or release can change either hold. Releasing the local hold performs the existing Stop/cleanup checks and leaves local transmission stopped. Releasing the remote hold only removes the additional restore gate; current pairing, revocation, receipt, and scheduling authority checks still apply. No remote device is stopped, adopted, reassigned, or commanded by restore. Saved enable-on-boot intent remains saved, and restart before explicit release cannot bypass the hold.

The frontend retains the previous admitted HTTP endpoint for recovery requests and downloads when listener ports change. Its private listener cache preserves that endpoint across frontend restart; it does not admit fresh sessions there or expose stale ordinary control routes. Restart verification checks the selected generation, saved settings digest, backend boot/readiness, both holds, and the frontend's admitted bound-listener presence where listeners are enabled. Results distinguish saved ports from active startup overrides. The production maintenance adapter uses those active ports to update only existing installer-managed Apache upstreams, preserves original configurations privately, runs the fixed Apache configuration check, and reloads the fixed Apache service. No site name, command, filesystem destination, or service is accepted from an archive or browser. A failed proxy reconciliation leaves the restore held and its original maintenance endpoint available for status and explicit recovery. Custom routes outside the installer-managed block are unchanged.

The installer extracts the maintained helper from the selected verified application image and packages the fixed isolated Python modules and dependency notices. `wsprrypi-maintenance.service` runs independently as root with private state and runtime directories. It is ordered before the backend and remains available with `--no-web`. The backend and maintenance roots remain inaccessible to the browser account. Updating the executable refuses an active maintenance job, stops the existing worker before replacing its executable/modules, and preserves application generations, archives, and recovery jobs. Packaging and service orchestration have temporary-directory/fake-command tests; actual installation and systemd lifecycle still require separate runtime qualification.

## Local maintenance commands

Run the installed executable as the local administrator. `--maintenance help` lists commands without opening storage. Backup creation and validation prompt through the controlling terminal with echo disabled; automation can supply private pipes or owner-only files through distinct descriptors numbered 3 or higher. Passphrase values are never command arguments or environment variables. A descriptor supplies one UTF-8 line of at most 1,024 bytes. The same maintenance worker and archive/owner validators serve the CLI and browser.

```sh
sudo wsprrypi --maintenance jobs
sudo wsprrypi --maintenance backup
sudo wsprrypi --maintenance status --job-id JOB_ID
sudo wsprrypi --maintenance download --job-id JOB_ID --output /absolute/new-backup.age
sudo wsprrypi --maintenance upload --file /absolute/backup.age
sudo wsprrypi --maintenance validate --job-id JOB_ID --purpose recover
sudo wsprrypi --maintenance validate --job-id JOB_ID --purpose move
sudo wsprrypi --maintenance confirm --job-id JOB_ID --preview-digest PREVIEW_SHA256
sudo wsprrypi --maintenance resume --job-id JOB_ID
sudo wsprrypi --maintenance cancel --job-id UNCONFIRMED_JOB_ID
sudo wsprrypi --maintenance review
sudo wsprrypi --maintenance release --review-digest CURRENT_REVIEW_SHA256 --local
sudo wsprrypi --maintenance release --review-digest CURRENT_REVIEW_SHA256 --remote
```

Create, validate, confirm, and recover return admitted or saved job state rather than waiting for completion. `jobs` returns compact summaries; `status` reads one full preview/result. This keeps four retained previews from exceeding the local control-frame bound. Poll `status`; do not replay an operation because its response was lost. A failed upload remains visible in `jobs` and can be cancelled before a new upload. Download streams the same pinned encrypted artifact as Maintenance, verifies its digest, uses a private temporary output, and refuses to overwrite an existing destination. Backup downloads remain possible when the backend is unavailable. The local privileged path works when browser admission, Apache, or the web process is unavailable, provided the backend can validate the selected destination and the maintenance worker is available. It does not silently replace a corrupt established database or invent a destination identity; failed destination validation remains an explicit recovery requirement.

Completed restore history retains the original migration generation, the selected generation, and its immediate predecessor. An older generation remains retained while a current catalog credential path references it, including a resolved symlink; the existing 64-profile, three-credential-path limit bounds those dependencies. Root-private inode-bound ownership records and a durable cleanup inventory prevent deleting substituted directories or unknown files. Interrupted deletion resumes only for unselected owned history, with every remaining file checked against that inventory. A failed confirmed restore keeps its job/proofs pinned until destination review releases its holds or a newer admitted hold supersedes it; other terminal jobs remain subject to the four-job retention bound. None of this history metadata is exported in diagnostics or treated as restored permission.

Small backend control queries retain a 12-second child deadline. Stopped-backend candidate construction and sealing allow up to 30 minutes for bounded archive I/O on the destination card; they do not inherit that short query deadline. A timeout preserves the held job and its recovery evidence for explicit resume. These are lifecycle limits, not a storage-speed qualification or a promise that every supported archive size finishes on a particular card.
